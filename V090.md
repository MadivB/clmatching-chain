# v0.9 — continuous t0s + timing-uncertainty output

**v0.9 = the certified v0.8.9 chain + stage 6 (`--subtick`).** Launcher:
`run_v09.sh <FLOW.hdf5> <out_dir> [n_workers=8] [n_gpus=4]`.

## What stage 6 adds on top of v0.8.9

1. **Continuous t0s.** After every assignment stage is final, hits are
   grouped by their exact final t0; each group's light is re-predicted
   from scratch as ONE bag of hits (a single batched perceiver call for
   all groups — the interaction-level form validated by the v097
   superposition test), and the group time is refined on a 0.25-tick
   grid (±3 ticks) followed by the analytic quadratic minimum (9-point
   ±1-tick window, vertex acceptance ±0.75 — measured better than the
   2x2's 7-point/0.5). Membership is NEVER touched — eff(±160 ns) is
   bit-identical by construction and by measurement.
2. **Per-group timing uncertainty** (the v1 confidence foundation): the
   same quadratic gives the local χ² curvature `a`, and Δχ²=1 yields
   **σ_t = 1/√a ticks** per group. Delivered per hit as
   `hit_t0_sigma` (NaN = no quadratic fit; conservative fallback), and
   summarized per event in `row["phase3"]["subtick"]`
   (`sigt_med_ns` / `sigt_p90_ns`).
3. No calibration constants: the global bias (~+9 ns, template-shape
   systematic) is left in place — absolute time is not needed.

## Guards (all conservative; centered-window design)

- The 9-point window is CENTERED on the chain time (itself the full
  integer scan's argmin), so no pre-scan exists to edge out of.
- Non-convex fit or vertex beyond ±0.75 ticks → group keeps its chain
  time (counted `n_nonconvex` / `n_range`).
- Movement bounded to ±0.75 ticks; a correct hit cannot leave ±10.

## Measured — CERTIFIED 2026-09-02 (126 events, tag CLMatching_v0.9)

- Headline: **NS 96.50 / all-TPC 95.65 / LE 59.21** — identical to v0.8.9
  (eff invariant by construction and by measurement; 113-ev cert 0 failures,
  scan workload bit-identical).
- Resolution on correctly-assigned core hits (|Δ| ≤ 5 ticks, E-weighted):
  per-hit σ 9.20 → **8.58 ns**; per-group timing uncertainty σ_t delivered
  (median 0.54 ns, p90 ~7 ns).
- Stage E production form: SUM-mode amplitudes (members' stage-1
  amplitudes summed on support channels — measured equal to the
  superposition-exact collective render: 8.58 vs 8.59 ns), centered
  9-shift window, top-30 channels, ≥5 MeV groups. **1.6 s/ev.**
- Latency (file 1, 8 workers × 4 GPUs): 123.7 s/ev/worker =
  **61.8 s/ev/GPU** (v0.8.9-era chain was 78.1).

## v0.9.2 — calibrated 0-1 t0 confidence (tag CLMatching_v0.9.2)

Per-hit `hit_t0_conf` in [0,1]: 0 = high-likelihood wrong (impure t0),
1 = confident. Logistic combination (subtick_conf_model.json, fully
inspectable) of BOTH evidence families per t0 group:
quadratic-fit (curve contrast — the #2 feature overall — chi2/dof at the
minimum, fit status, sigma_t) + waveform comparison (mean |z| and
frac |z|>2 at the peak tick, cos(predicted pattern, residual)) +
logE/n_tpc/n_hits priors. File-1 leave-one-event-out: **combined AUC
0.881** vs 0.858 quadratic-only / 0.869 waveform-only; reliability
monotone 22% -> 99.8% across score bins. In-chain validation: metrics
bit-identical, conf >= 0.95 holds 98% of energy at 96.2% correct;
impure-t0 groups (10% by count, 0.8% by energy) concentrate at the low
end. NaN = no estimate (sub-5 MeV light-blind groups). Trained on file
0000001 only (user: sufficient statistics; re-fit on files 2-10 before
any physics cut is published).


## v0.10.0 — cluster-level three-family confidence (tag CLMatching_v0.10.0)

`--conf-cluster` (requires `--subtick`): per-hit `hit_t0_conf` is now the
CLUSTER-level calibrated probability that the cluster's t0 assignment is
correct (the v0.9.2 group-level score moves to `hit_t0_conf_group`).

Three evidence families, HGB + isotonic (subtick_conf_model3.joblib, built
by subtick_conf_study3.py; deep-research notes in
testing/CONFIDENCE_RESEARCH.md):
1. 40 v0.8.3 cluster features - 29 spatial orphan-ness + the anchored-
   covariance swap-aware block (z_min/z_own/dz/chi2_loc/n_tpc) + basics.
2. 10 v0.9.2 t0-group features (quadratic fit + waveform comparison).
3. 8 NEW scan-landscape features (scan_margin.py, PDA/JPDA-inspired):
   valley depth and competitor Delta-chi2 margin in per-cluster
   empirical-temperature units, rel_margin, competing-minima count, PDA
   posterior incl. an explicit no-light null, valley width, and
   |scan argmin - placement|. Computed from the final loss landscape via
   FFT correlation with the group-share rescale (collective render is NOT
   the sum of member renders - v097) and veto/CLIP channels excluded.

Measured (file 0000001, 17772 clusters, 4450 wrong = 3.13% of energy):
- honest LOO: AUC 0.850 count / 0.970 E-weighted
  (bands 0.859 / 0.932 / 0.953 in 5-20 / 20-100 / >=100 MeV);
  study2 two-family winner was 0.817/0.947; scan block alone 0.752/0.951.
- at a 10% flag rate: 1284/4450 wrong clusters caught at 72% purity.
- combination rule: a learned joint model beats min(worse-of-two) 0.803
  and product 0.833 - both tested per user's proposal.
- in-chain validation (v127): headline metrics BIT-IDENTICAL, 0 errors;
  in-sample (trained on this file) AUC 0.903/0.989, low bin 0.3% correct,
  top bin 99.8%. RE-FIT on files 2-10 before any physics cut is published.
- cost: median 4.2 s/ev (max 7.7) ~ +2.1 s/ev/GPU; dominated by the
  40-feature spatial block (cluster_rows ~4 ms/cluster) - first
  optimization target if latency matters.

## v0.10.1 — RULE-BASED confidence, no ML in the data path (tag CLMatching_v0.10.1)

User directive 2026-09-03: the method runs directly on data, so no
MC-trained model in the delivered chain. `--conf-cluster` now applies a
4-check rule (conf_rule_v0101.json, plain JSON):

    check 1: rel_margin  >= 0.83   beats its best competitor valley
    check 2: pcu_vote10  >= 0.46   channels AGREE on the location
    check 3: pcu_sig_med >= 10.9   per-channel minima CLEAR, not flat
    check 4: c_cosres    >= 0.97   residual pattern matches own light shape
    level = number of passed checks; delivered conf = the level's measured
    E-weighted purity (5-entry lookup, tuned once on file-0000001 MC):
    level 0..4 -> 0.49 / 0.72 / 0.91 / 0.99 / 1.00

All four checks come from the scan-landscape block (light data only,
GPU-batched FFT) — no spatial features, no cluster_rows, no anchored
covariance at serving time. Three independent methods picked these
variables: the user's read of the feature histograms, the threshold
search, and held-out ML permutation importance (pcu_vote10 #1 at 3x the
runner-up).

Measured (file 0000001, 17.8k clusters):
- E-weighted AUC 0.961 (retired 79-feature HGB: 0.975; the -0.014 buys
  full transparency); count AUC 0.753 (small light-blind clusters lose
  their spatial evidence — known trade).
- in-chain validation v129: headlines BIT-IDENTICAL, 0 errors; per-level
  delivered-vs-measured purity agrees within <= 0.013 at every level.
- stage cost 0.78 s/ev median (max 1.27) — 5.4x faster than the ML stage.
- level 4 alone holds 65.3% of all energy at 99.5-100% purity;
  levels 3+4 = 87.5% of energy at >= 98%.

The ML path (subtick_conf_model5.joblib etc.) is retained for DEVELOPMENT

## v0.10.2 — lean product confidence + purity calibration (tag CLMatching_v0.10.2)

User redesign 2026-09-04, replacing the v0.10.1 count rule:

    raw  = pcu_vote10                       (the backbone - best discriminator)
           x 0.5 if c_cosres  < 0.71        (side-help penalty, fires 26%)
           x 0.5 if rel_margin < 0.56       (side-help penalty, fires 30%)
    conf = piecewise-linear map of raw through 8 measured purity knots
           (0.30 ... 0.997); light-blind clusters -> 0.59 (measured prior)

Design decisions, all measured:
- pcu_sig_med DROPPED: at side-help thresholds its fires are 50-60%
  redundant with low vote10 (flat channels CAUSE scattered votes) and its
  unique catch is ~0.1 GeV. 2D overlap figure: v0102_2d_overlap.png.
- The v0.10.1-era heavy penalties (firing 55-77%) bought E-wt AUC 0.962 by
  crushing half the CORRECT clusters to score ~0 (129 GeV of correct energy
  penalized by one cut alone). Rejected: values must mean what they say.
- Calibration map = measured E-weighted bin purity -> the delivered number
  IS a probability again; floor 0.30 means "evidence against" (30% pure),
  not "no information".

Measured (file 0000001, 17813 clusters incl. light-blind):
- delivered conf: correct median 0.88, ZERO correct clusters below 0.3;
  wrong median 0.59; only 8% of wrong clusters above 0.9 (high-vote wrongs,
  invisible to light).
- AUC 0.763 count / 0.933 E-weighted (full population).
- v131 in-chain validation: headlines BIT-IDENTICAL, 0 errors, 0.71 s/ev
  median; in-chain distribution matches offline design exactly.
- rule file: testing/conf_rule_v0102.json (2 thresholds + 2 factors +

## v0.10.3 — ZERO-MC two-variable confidence (tag CLMatching_v0.10.3)

User direction 2026-09-04: only pcu_vote10 + rel_margin, and no serious
MC-truth use. Final form (conf_rule_v0103.json, mode "formula"):

    conf = pcu_vote10  x  rel_margin / (1 + rel_margin)
    light-blind clusters -> NaN (no estimate)

NO MC-tuned numbers in the score. Interpretation: witness agreement
(amp-weighted fraction of light channels whose own loss minimum is within
+-10 ticks of the placement) x two-hypothesis posterior that the chosen
valley beats its best rival (odds = rel_margin; 0.5 when the rival is
equally deep, ->1 as it vanishes). MC truth used ONLY for validation.

Development ladder (all measured, scan clusters, file 0000001):
  vote10 alone 0.911 E-wt -> +hard rm penalty 0.942 -> tuned soft 0.946
  -> 5x5 MC purity table 0.951 (rejected: 25 MC numbers)
  -> Hill formula 0.955 E-wt / 0.807 count with ZERO MC numbers -
  the formula encodes the physics as structure instead of memorizing
  purities, and outperforms the table.
Dropped: pcu_sig_med (redundant with vote10 - flat channels cause
scattered votes), c_cosres (rel_margin alone beats the cos+rm pair).

v133 in-chain validation: headlines BIT-IDENTICAL, 0 errors, 0.74 s/ev;
in-chain AUC 0.807/0.955 = offline exactly.

Validation-only reading key (file 1): conf>=0.9 -> 99.8% E-pure (75.8% of
E); 0.7-0.9 -> 98.6%; 0.5-0.7 -> 94.4%; 0.3-0.5 -> 87.0%; <0.1 -> 49%.
Figures: v0103_conf_hist.png, v0102_four_variables[_clean].png.
