## Canonical invocation

v0.4.1 flags plus the front-end switch:

```
--backbone stack2 --merge-p2 --sigma-mode poisson --max-clip-ticks 4
--police locked --merge-vertex --skip-baseline --phase3 both --force-coverage
--swap-fix --swap-ratio-max 0.85 --p2-threshold 30 --predict-min-energy 1.5
--frontend-repo /global/cfs/cdirs/dune/users/yuxuan/NDLAr-full/clmatching-frontend
```

(Omit `--frontend-repo` → built-in v0.5.5 clustering; `--frontend-params`
selects a different params json, default `<repo>/params_full.json`.)

## Update workflow

1. Develop/tune in the front-end repo (locally or here), `git push` / `git pull`.
2. Re-run `testing/interactive_v057fe.sh` (quick, 1 file) — compare against
   `testing/v056rel_out` (built-in baseline, same file).
3. Adopt when better; full statistics via `interactive_v060full.sh`.

Known open lever: the external chain emits no `shower`-typed labels (all
backbone objects are `track`), so the chain's shower fast-path is empty and
former showers ride the merged permutation pool. Re-typing ≥N-track vertex
groups, or widening their support channels, is the first assignment-side
tuning candidate.
